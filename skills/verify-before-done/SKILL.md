# הוכחה לפני סיום (verify-before-done)

> עיבוד לעברית של הסקיל `verification-before-completion` מתוך [superpowers](https://github.com/obra/superpowers) מאת Jesse Vincent, רישיון MIT. ראה `THIRD_PARTY_NOTICES.md`.

## העיקרון

**הוכחה לפני טענות, תמיד.**

**לעבור על האות של הכלל זה לעבור על רוחו.**

## החוק הברזל

```
אין טענת סיום בלי ראיית אימות טרייה
```

לא הרצת את פקודת האימות בהודעה הזאת? אסור לך לטעון שהיא עוברת.

## שער האימות

```
לפני שאתה טוען כל סטטוס או מביע שביעות רצון:

1. זהה: איזו פקודה מוכיחה את הטענה?
2. הרץ: את הפקודה המלאה (טרייה, שלמה)
3. קרא: את כל הפלט, בדוק קוד יציאה, ספור כשלונות
4. אמת: האם הפלט מאשר את הטענה?
   - לא: דווח את המצב האמיתי עם הראיה
   - כן: טען את הטענה יחד עם הראיה
5. רק אז: טען

דילוג על שלב = שקר, לא אימות
```

## כשלונות נפוצים

| טענה | מה נדרש | מה לא מספיק |
|------|---------|-------------|
| הבדיקות עוברות | פלט פקודת הבדיקות: 0 כשלונות | הרצה קודמת, "אמור לעבור" |
| ה-linter נקי | פלט ה-linter: 0 שגיאות | בדיקה חלקית, הסקה |
| ה-build עובר | פקודת ה-build: exit 0 | ה-linter עבר, הלוגים נראים טוב |
| באג תוקן | בדיקת הסימפטום המקורי: עוברת | שינית קוד, הנחת שתוקן |
| בדיקת רגרסיה עובדת | מחזור אדום-ירוק אומת | הבדיקה עברה פעם אחת |
| סוכן סיים | ה-diff ב-git מראה שינויים | הסוכן דיווח "הצלחה" |
| הדרישות התקיימו | צ'קליסט שורה אחרי שורה | הבדיקות עוברות |

## דגלים אדומים: עצור

- שימוש ב"אמור", "כנראה", "נראה ש"
- הבעת שביעות רצון לפני אימות ("מעולה!", "סבבה!", "גמרנו!")
- עומד לעשות commit, push או PR בלי אימות
- סומך על דיווח הצלחה של סוכן
- נשען על אימות חלקי
- חושב "רק הפעם"
- עייף ורוצה לסיים
- **כל ניסוח שמרמז על הצלחה בלי שהרצת אימות**

## מניעת תירוצים

| תירוץ | המציאות |
|-------|---------|
| "אמור לעבוד עכשיו" | הרץ את האימות |
| "אני בטוח" | ביטחון אינו ראיה |
| "רק הפעם" | אין יוצאים מן הכלל |
| "ה-linter עבר" | linter אינו קומפיילר |
| "הסוכן אמר שהצליח" | אמת בעצמך |
| "אני עייף" | עייפות אינה תירוץ |
| "בדיקה חלקית מספיקה" | חלקית לא מוכיחה כלום |
| "ניסוח אחר, אז הכלל לא חל" | הרוח קודמת לאות |

## תבניות

**בדיקות:**
```
✅ [הרצת פקודת הבדיקות] [רואה: 34/34 עוברות] "כל הבדיקות עוברות"
❌ "אמור לעבור עכשיו" / "נראה נכון"
```

**בדיקות רגרסיה (TDD אדום-ירוק):**
```
✅ כתוב → הרץ (עוברת) → בטל את התיקון → הרץ (חייבת ליפול) → החזר → הרץ (עוברת)
❌ "כתבתי בדיקת רגרסיה" (בלי אימות אדום-ירוק)
```

**Build:**
```
✅ [הרצת build] [רואה: exit 0] "ה-build עובר"
❌ "ה-linter עבר" (linter לא בודק קומפילציה)
```

**דרישות:**
```
✅ קרא שוב את התוכנית → בנה צ'קליסט → אמת כל פריט → דווח על פערים או על השלמה
❌ "הבדיקות עוברות, השלב גמור"
```

**האצלה לסוכנים:**
```
✅ הסוכן מדווח הצלחה → בדוק את ה-diff ב-git → אמת את השינויים → דווח את המצב האמיתי
❌ לסמוך על דיווח הסוכן
```

## מתי להפעיל

**תמיד לפני:**
- כל וריאציה של טענת הצלחה או סיום
- כל הבעת שביעות רצון
- כל אמירה חיובית על מצב העבודה
- commit, יצירת PR, סיום משימה
- מעבר למשימה הבאה
- האצלה לסוכנים

**הכלל חל על:**
- ניסוחים מדויקים
- פרפרזות ומילים נרדפות
- משמעויות מרומזות של הצלחה
- כל תקשורת שמרמזת על סיום או נכונות
